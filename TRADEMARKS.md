# SCP DNA — Trademarks and Project Names

> **Legal notice:** This policy is a practical project policy, not a determination of trademark ownership or registration status. Replace the placeholders and have a qualified trademark professional review it before publication.

## 1. Project marks

The project uses or claims the following names and marks, subject to applicable law and actual ownership:

```text
SCP DNA
SCP
GA-LAB
[PROJECT LOGO / WORDMARK]
[OTHER OFFICIAL PRODUCT NAMES]
```

Copyright and open-source licenses for code do **not** automatically grant permission to use these names, logos, or marks to imply that a fork, service, distribution, or commercial product is official or endorsed.

## 2. What the code licenses permit

The applicable code license may allow copying, modification, and distribution of code. It does not by itself grant permission to:

- Claim that an unofficial fork is the official SCP DNA project.
- Use the SCP DNA or GA-LAB logo in a product, website, package, or service without permission.
- Use the marks in a way that creates confusion about source, sponsorship, endorsement, or maintenance.
- Register a confusingly similar name or logo for a derivative product.
- Remove required copyright, license, or attribution notices.

The Apache License explicitly states that it does not grant trademark rights. AGPL rights should likewise be read as code-license rights, not as a general brand license.

## 3. Permitted descriptive use

The following uses are generally intended to be allowed, subject to accuracy and applicable law:

- “Built with SCP DNA” when the product actually includes or uses the project and the statement is not presented as official endorsement.
- “SCP DNA-compatible” when the implementation genuinely follows the documented interface and does not claim official status.
- “An unofficial fork of SCP DNA” when the fork has a distinct product name and clearly identifies that it is not maintained or endorsed by GA-LAB.
- Referencing “SCP DNA” in documentation to identify the upstream project accurately.

Descriptive use must not alter the official logo or create a visual presentation likely to confuse users.

## 4. Fork naming rule

An unofficial fork should use a distinct name. Recommended form:

```text
[NEW PRODUCT NAME]
An unofficial fork of SCP DNA
```

Do not name an unofficial fork:

```text
Official SCP DNA Enterprise
GA-LAB SCP Official
SCP DNA Cloud by [third party]
```

unless the copyright holder has granted written permission.

## 5. Logo and visual identity

Do not copy, modify, recolor, animate, or combine the official logo with another product logo without written permission. Do not use the official logo in a marketplace listing, hosted service, training course, or certification badge in a way that implies approval.

The project may publish a separate brand kit specifying allowed colors, clear space, and approved logo files.

## 6. Commercial use and partnership

A commercial license for code does not automatically grant trademark permission. A commercial customer, reseller, integrator, or hosting provider must obtain separate written permission if it wants to use project marks beyond accurate descriptive reference.

Any approved partner permission should identify:

- The exact mark and artwork.
- The approved product, website, or service.
- The approved territory and duration.
- Whether the use is revocable.
- Required attribution and disclaimer.
- Whether the use implies partnership, certification, or endorsement.

## 7. Enforcement and contact

The project may request that an unauthorized user stop confusing, misleading, or infringing use of project marks. This policy does not promise that every use is legally infringing; questions should be reviewed under applicable law.


Before publication, confirm that the contact address is controlled by the actual project owner and that any remaining logo/mark placeholders have been resolved.

## 8. Relationship to the code licenses

This policy does not change the terms of `AGPL-3.0-only`, `Apache-2.0`, or any third-party license. It only describes project-name and brand usage. If a third-party component has its own trademark policy, that policy also applies to that component.
