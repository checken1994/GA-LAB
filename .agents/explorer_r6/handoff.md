## 2. Logic Chain

1. **Premise 1 (From Observation 1)**: Rollback mechanisms in `autofix_mixin.py` and `code_evolution_agent.py` store pre-patch states in Python process RAM variables (`ctx.pre_fix_content` and `backup`).
2. **Inference 1**: Because RAM state does not survive process termination, any process crash, OOM event, unhandled `SystemExit`, or machine reboot that occurs during patch testing leaves target files permanently modified on disk without any means of recovery.
3. **Premise 2 (From Observation 2)**: Backups written to disk are dumped directly into source directories beside `.py` files.
4. **Inference 2**: This violates the Clean Workspace non-negotiable rule, contaminates Git status, confuses linters, and allows successive patches on the same file to clobber previous backups.
5. **Premise 3 (From Observation 3 & 4)**: The pytest verification gate is turned off by default, targets the source file instead of test suites, fails open on errors, and Tier 3 auto-approve ignores `SyntaxError` during reality testing.
6. **Inference 3**: Corrupted or regressive code generated by LLMs or pattern fixers can be marked as `fixed` and committed to the codebase without failing closed.
7. **Synthesis Conclusion**: R6 cannot achieve autonomous 24/7 isolation until a dedicated, filesystem-backed, crash-resilient transaction manager (`data/shadow/active/<tx_id>/`) is implemented with strict fail-closed pytest enforcement and startup crash reconciliation.

- The test suite in `tests/T07_learning/` currently tests high-level classifier behavior and epistemic missing piece discovery; it does not currently assert physical crash recovery of aborted AutoFix transactions.

## 4. Conclusion

The AutoFix and Cognitive loop subsystems lack atomic snapshot isolation and crash recovery. To resolve R6:
1. Implement `ShadowSnapshotManager` at `scp/autofix/shadow_snapshot.py` to manage transactions under `data/shadow/`:
   - `begin(target_files, bug_id)`: creates atomic directory in `data/shadow/active/<tx_id>/` with pre-patch file backups and manifest.
   - `rollback(tx_id, reason)`: performs atomic file restoration via temp file + `fsync` + `os.replace`.
   - `commit(tx_id)`: moves transaction to `data/shadow/completed/`.
   - `recover_abandoned_transactions()`: runs during engine startup to roll back any transactions abandoned by crashed processes.
2. Refactor `autofix_mixin.py` (`_auto_fix_part1` and `_auto_fix_part3`) and `code_evolution_agent.py` to execute patches strictly within `ShadowSnapshotManager` transactions.
3. Eliminate ad-hoc `.tier3bak`, `.audit_fix_backup`, and `.evolutionbak` files in the source tree.
4. Fix `verify_mixin.py` pytest gate: enable by default, map modified modules to relevant `tests/` targets, and ensure fail-closed on any test failure or exception.
5. Fix `_auto_approve_tier3` in `engine.py` to trigger rollback if `_reality_test_result` is not `PASS`.
