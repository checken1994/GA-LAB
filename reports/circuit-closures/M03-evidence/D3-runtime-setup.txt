## Why a temporary instance (and why profile=full)

Main deployment runs SCP_API_PROFILE=core → route groups "openai_compat" and
"versioned_admin" (which carries the swe_bench router in api_server.py) are
not registered → 404 at the main instance (observed, D2-docker.txt). All M3
route probes ran on a TEMPORARY instance scp-m3-std on 127.0.0.1:8002 ->
8000 (container), same pinned image, own data volume scp-m3-std-data,
torn down after the probes. Port 8001 was occupied by another stack
(scp_v2-llm-gateway-1), hence 8002.

## Temp instance configuration (env overrides, all disclosed)

- docker run flags mirror compose hardening: --read-only, tmpfs /tmp
  (noexec,nosuid), --cap-drop ALL, --security-opt no-new-privileges:true.
- SCP_API_PROFILE=full (registers openai_compat AND versioned_admin/swe-bench
  route groups — the surface the D1 contract suite runs under, tests/conftest.py).
- SCP_EGRESS_MODE=deny kept for the whole session. No external LLM/provider
  was called by any probe (the judge path with ai_answer="" rejects at tier1
  REJECT_EMPTY before any provider call; elapsed_ms ~0.6 confirms no network).
- Credential neutralisation for determinism (config removal, not mocking):
  OPENROUTER_API_KEY.._10 (+ *_FILE variants), GEMINI_API_KEY, GROQ_API_KEY,
  GROQ_API_KEY_2, CEREBRAS_API_KEY, SAMBANOVA_API_KEY, NVIDIA_API_KEY.._3,
  OPENAI_API_KEY/OPENAI_BASE_URL/OPENAI_MODEL all set EMPTY (25 names,
  _neutralized_keys.txt). No provider subsystem was mocked.
- JWT minted INSIDE the container from SCP_JWT_SECRET via
  scp.security.jwt_guard.create_access_token; the token value was never
  printed or stored in the repo (passed via process env to the probe script).
