## Why a temporary instance

Main deployment runs SCP_API_PROFILE=core -> route group "chat" is not
registered -> WS /chat handshake returns 403 at router level (before auth).
Per closure plan (mirroring the earlier S6a/Agent-A approach), WS runtime
evidence was collected on a TEMPORARY standard-profile instance on
127.0.0.1:8001 (host) -> 8000 (container), same image, own data volume
(scp-m2-std-data, isolated from the main deployment's volume), torn down
after the probes.

## Temp instance configuration (env overrides, all disclosed)

- docker run flags mirror compose hardening: --read-only, tmpfs /tmp
  (noexec,nosuid), --cap-drop ALL, --security-opt no-new-privileges:true.
- SCP_API_PROFILE=standard (registers the /chat route group).
- Credential neutralisation for probe determinism (same isolation class as
  the D1 test helper `_disable_openrouter`): OPENROUTER_API_KEY.._10,
  GEMINI_API_KEY, GROQ_API_KEY, GROQ_API_KEY_2, NVIDIA_API_KEY.._3,
  CEREBRAS_API_KEY, SAMBANOVA_API_KEY all set EMPTY. These are config
  removals; no provider subsystem was mocked.
- Local answer source: real HTTP OpenAI-compat fixture server inside the
  container on 127.0.0.1:9101 (reports/circuit-closures/M02-evidence/
  _fixture_server.py), identical response shape to the D1 contract-test
  fixture (judge prompts containing "PASS or FAIL" -> "PASS"; chat prompts ->
  fixed Vietnamese answer). Provider wiring via production env contract:
  OPENAI_API_KEY/OPENAI_BASE_URL/OPENAI_MODEL -> EnvCompatProvider
  ("openai_compat"), chain for chat AND judge tasks = [openai_compat:enabled].
- Zero-cost wall: first gateway call returned err=zero_cost_denied:
  DENY_UNKNOWN_PRICE (fail-closed pricing ledger — observed, not assumed).
  Seeded a $0 pricing proof for provider=openai_compat, model=m2-local-model
  via the OFFICIAL proof-store API (get_runtime_guard().proof_store.record,
  evidence_id price://m2-local-fixture) — the same step the D1 contract test
  performs (_seed_zero_cost_proof). After seeding, gateway chat returned the
  fixture answer with provider label openai_compat:m2-local-model.
- SCP_MULTI_LLM_CROSSCHECK=0: the multi-LLM crosscheck requires TWO distinct
  provider families; with a single-provider fixture deployment it fails
  closed (observed: verdict UNKNOWN, failures=["semantic_judge_unavailable"],
  ESCALATE). The D1 contract tests pin the same env (test file lines 407/450).
- Egress policy stayed SCP_EGRESS_MODE=deny for the whole session; loopback
  fixtures are allowed by policy design (egress_policy.py docstring +
  llm_egress_allowed loopback branch). No external LLM/provider was called.
